# App.vue

Компонент є головним інтерфейсом застосунку, що надає користувачеві можливість керувати підключенням до Omlx-черги та взаємодіяти з агентами. Він відображає статус черги, історію запитів та надає панель для аналізу ланцюжків.

## Поведінка
1. **Ініціалізація при старті:**
    * Отримується версія застосунку.
    * Якщо API-ключ відсутній у локальному сховищі, він зчитується з оточення.
    * Якщо API-ключ знайдено, ініціюється підключення до Omlx-черги та запуск локального проксі.
    * Завантажуються моделі для агента.
2. **Підключення/Відключення:**
    * При натисканні "Підключити" зберігаються дані підключення та ініціюється підключення до Omlx-черги.
    * Якщо підключення успішне, запускається локальний проксі.
    * При натисканні "Відключити" зупиняється проксі та розривається з'єднання з чергою.
3. **Управління діалогами:**
    * Відкриття/закриття діалогу агента за допомогою кнопки "Агент".
    * Відкриття/закриття діалогу журналу запитів за допомогою кнопки "Журнал запитів агента".
    * Відкриття діалогу сесії для записів історії.
    * Відкриття діалогу аналізу ланцюжка.
4. **Перегляд черги (вкладка "Черга і запити"):**
    * Відображається стан кожної моделі в черзі: активні завдання, завдання в черзі.
    * Для активних завдань відображається прогрес генерації (токенів, tok/s, час).
    * Для завдань у черзі відображається позиція, кількість токенів промпту та час очікування.
    * Можливість очистити історію запитів.
5. **Перегляд ланцюжків (вкладка "Ланцюжки"):**
    * Відображається панель для взаємодії з ланцюжками.
    * При виклику аналізу ланцюжка, ініціюється відкриття діалогу аналізу з відповідним промптом.
6. **Історія запитів:**
    * Відображається список усіх запитів, що пройшли через проксі.
    * Кожен запис можна розгорнути для перегляду деталей клієнта, запиту та відповіді.
    * Можливість копіювати JSON-об'єкт запиту або відповіді у буфер обміну.
    * При натисканні на запис, відкривається діалог для сесії аналізу (з доступом до файлової системи клієнта).
7. **Аналіз ланцюжка:**
    * При збереженні результату аналізу ланцюжка, він зберігається у системі та оновлюється відповідний бейдж.

## Гарантії поведінки
* При відключенні всі активні процеси та з'єднання з чергою припиняються.
* Інтерфейс відображає коректний статус підключення (підключено/не підключено) та статус проксі.
* Деталі запитів у журналі відображаються з коректним форматуванням часу та тривалості.
* Функціонал аналізу ланцюжка гарантує збереження результату у вказаному шляху та оновлення стану відповідних компонентів.

# App.vue

Компонент є головним інтерфейсом застосунку, що надає користувачеві можливість керувати підключенням до черги Omlx, взаємодіяти з агентом та переглядати історію запитів. Він агрегує різні модулі для управління чергою, проксі, агентом та аналізом ланцюжків.

## Поведінка
1. **Ініціалізація при старті:**
    * Отримується версія застосунку.
    * Якщо API-ключ відсутній у локальному сховищі, він зчитується з оточення процесу.
    * Якщо API-ключ знайдено, ініціюється підключення до черги та запуск локального проксі.
    * Завантажуються моделі для агента.
2. **Керування підключенням:**
    * Користувач може вводити URL-адресу та API-ключ для підключення до черги.
    * При натисканні "Підключити" зберігається конфігурація, ініціюється підключення до черги, а потім запускається локальний проксі.
    * При натисканні "Відключити" зупиняється проксі та розривається з'єднання з чергою.
3. **Управління інтерфейсом:**
    * Відкриття/закриття діалогу Агента за допомогою кнопки.
    * Відкриття/закриття діалогу Журналу запитів.
    * Перемикання між вкладками "Черга і запити" та "Ланцюжки".
4. **Відображення черги:**
    * Якщо черга підключена, відображається список активних моделей.
    * Для кожної моделі відображається кількість активних та очікуючих запитів.
    * Відображається прогрес генерації токенів для активних запитів (ідентифікатор, кількість токенів, швидкість, час).
    * Відображається список запитів у черзі (ідентифікатор, позиція, токени промпту, час очікування).
5. **Історія запитів:**
    * Відображається список усіх запитів, що пройшли через проксі.
    * Кожен запис відображає шлях, час, статус, модель та ідентифікатор.
    * Можливість розкрити деталі запиту, включаючи інформацію про клієнта, повний запит та відповідь.
    * Можливість копіювати JSON-об'єкти запиту та відповіді у буфер обміну.
    * Можливість відкрити сесію аналізу через Pi для вибраного запиту.
    * Можливість очистити історію запитів.
6. **Аналіз ланцюжків:**
    * Через вкладку "Ланцюжки" відображається інформація про ланцюжки.
    * При виборі ланцюжка, користувач може ініціювати аналіз, що відкриває діалог.
    * Після завершення аналізу, результат зберігається у файлову систему, і оновлюється інтерфейс.

## Гарантії поведінки
* При відключенні з'єднання з чергою, усі локальні проксі-сервери зупиняються.
* При ініціалізації, застосунок намагається автоматично підключитися, якщо API-ключ доступний.
* Деталі запиту в історії можуть бути розкриті або згорнуті за потреби користувача.
* Збереження аналізу ланцюжка гарантує, що результат буде збережено у визначеній системній директорії.
* При спробі відкрити сесію аналізу через Pi, система перевіряє наявність робочої директорії клієнта та наявність завантажених моделей.

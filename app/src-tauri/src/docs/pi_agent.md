## Огляд

Огляд: Цей файл забезпечує механізм ініціації та управління викликами зовнішнього кодинг-агента `pi` (<https://pi.dev>) з інтерфейсу клієнта проксі-запиту. Він дозволяє користувачу вибрати модель із доступних, визначених через змінні оточення, і ініціює короткоживучі виклики `pi` для виконання завдань. Безперервність розмови підтримується самим агентом `pi` через сесійний файл на диску; агент отримує повний read/bash/edit/write доступ до коду проєкту за вказаним шляхом.

Поведінка:
PiAgentError описує можливі помилки під час взаємодії з агентом `pi`, які перехоплюються у режимі fail-safe, що означає, що винятки не передаються назовні. При певних помилках замість кидання винятку повертається порожнє значення (наприклад, null).
PiModelOption представляє опцію моделі, доступну для вибору, фіксуючи ключ змінної оточення, зручну мітку та фактичне ім'я моделі для використання в `pi`.
pi_agent_models знаходить та повертає список усіх моделей, визначених у змінних оточення, які відповідають конвенції `N_*_MODEL`.
run_pi_agent запускає зовнішній агент `pi` з заданими параметрами — директорією, обраною моделлю, ідентифікатором сесії та початковим запитом. Функції є read-only; вони не здійснюють записів у файлову систему чи бази даних.

## Поведінка

Поведінка:
PiAgentError описує можливі помилки, які виникають при взаємодії з агентом `pi`, включаючи невдалий запуск або завершення процесу з ненульовим кодом.
PiModelOption представляє опцію моделі, доступну для вибору, зберігаючи ключ змінної оточення, зручну мітку та фактичне ім'я моделі для використання в `pi`.
pi_agent_models знаходить усі визначені в змінних оточення, що відповідають конвенції `N_*_MODEL`, і повертає список доступних варіантів моделей.
run_pi_agent запускає зовнішній агент `pi` з заданими параметрами, зокрема вказаною директорією, обраною моделлю, ідентифікатором сесії та початковим запитом, повертаючи вивід виконання агента або повідомлення про помилку.

## Публічний API

PiAgentError — обробляє помилки, які виникають під час роботи агента, забезпечуючи стійкість процесу.
PiModelOption — визначає та керує вибором моделі, яку використовує агент для генерації відповідей.
pi_agent_models — автоматично сканує середовище на наявність конфігурацій нових AI-моделей, дозволяючи додавати нові провайдери через зміну змінних середовища у форматі `N_<TIER>_MODEL` без модифікації коду.
run_pi_agent — ініціює виконання агента, використовуючи визначені в конфігурації параметри для взаємодії з AI-моделями, як це описано на <https://pi.dev>.

## Гарантії поведінки

- Read-only: не виконує операцій запису (ФС/БД).
- Перехоплює помилки і не пропускає винятків назовні (fail-safe).
- За певних помилок повертає порожнє значення (напр. `null`) замість винятку.

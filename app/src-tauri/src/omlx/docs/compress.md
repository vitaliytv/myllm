# compress.rs

## Огляд

Функція стискає тіло запиту `chat-completions` перед форвардом через `proxy_handler` (`proxy.rs`). Стиснення мінімізує вбудований pretty-printed JSON у текстовому `content` та обрізає старі великі блоки для зменшення розміру. Запит зі структурованим `response_format` пропускається незмінним. Повідомлення з tool-викликами (`tool_calls`/`function_call`/`role: tool`) залишаються byte-exact по-повідомленнєвому, оскільки компресія не застосовується до всього блоку. Захист `system`-повідомлень знімається, якщо сумарний розмір запиту перевищує `SYSTEM_TRUNCATION_SIZE_THRESHOLD`, що дозволяє часткову втрату каталогу skills замість повної відмови prefill. Канонічна логіка компресії (spec 2026-07-06-proxy-retirement) реалізована на клієнті у `@nitra/llm-lib/lib/internal/compress-context.mjs`.

## Поведінка

1. Викликається функція compress_request_body для обробки тіла запиту.
2. Функція перевіряє, чи містить тіло запиту масив повідомлень. Якщо ні, повертається `None`.
3. Функція перевіряє, чи містить тіло запиту поле structured `response_format`. Якщо так, повертається `None`, і запит залишається незмінним.
4. Визначається, чи є системне повідомлення захищеним від обрізання на основі загального розміру сирого тіла запиту.
5. Визначається індекс останнього повідомлення, яке не підлягає обрізанню (захищений хвіст).
6. Ітерується по кожному повідомленню в запиті.
7. Якщо повідомлення містить дані про tool-виклик, function-call або має роль `tool`, воно копіюється без змін.
8. Для інших повідомлень визначається, чи є воно системним, і застосовується відповідне правило захисту (системний захист або позиційний захист хвостового повідомлення).
9. Для кожного повідомлення викликається compress_message.
10. Якщо повідомлення містить текстовий контент, викликається compress_text.
11. compress_text спочатку намагається мінімізувати вбудований JSON у тексті.
12. Якщо повідомлення захищене або після мінімізації його розмір не перевищує встановлений поріг, воно приймається.
13. Якщо повідомлення не захищене і перевищує поріг, його текст обрізається, зберігаючи початок та кінець.
14. Якщо повідомлення містить мультимодальний контент, викликається compress_parts, який застосовує мінімізацію лише до текстових частин.
15. Якщо будь-яке повідомлення було змінено, створюється новий об'єкт запиту з оновленим масивом повідомлень.
16. Якщо жодне повідомлення не було змінено, повертається `None`.

## Публічний API

compress_request_body — стискає тіло запиту чат-відповіді, якщо це можливо, і повертає стиснене тіло або `None` за певних умов.

## Гарантії поведінки

- Read-only: не виконує операцій запису (ФС/БД).
- За певних помилок повертає порожнє значення (напр. `null`) замість винятку.

# proxy.rs

## Огляд

Модуль реалізує зворотний проксі для трафіку `/v1/*` до omlx. Він виступає посередником для клієнтів (mlmail, myshare, `mcp-omlx.mjs`), які звертаються на локальний порт проксі замість прямого доступу до `:8000`. Проксі пересилає запит до omlx один в один і паралельно стрімить копію в лог. Це забезпечує збір повної історії запитів та відповідей, оскільки Admin API omlx надає лише поточний стан. Механізм реалізує fail-safe обробку помилок, перехоплюючи їх та повертаючи порожнє значення замість винятків.

## Поведінка

ProxyError описує можливі помилки, що виникають під час роботи проксі.
RequestLogEntry описує структуру запису в лог, що містить деталі кожного HTTP-запиту та відповіді.
ProxyRuntime зберігає хендл живого проксі-таска для можливості його зупинення.
proxy_start ініціалізує та запускає проксі-сервер на заданому порту, повертаючи фактичний порт, на якому він слухає.
proxy_stop припиняє роботу запущеного проксі-сервера.
proxy_history зчитує та повертає останні записи з лог-файлу `requests.jsonl` у директорії даних застосунку.
proxy_clear_history видаляє лог-файл `requests.jsonl` з директорії даних застосунку.

## Публічний API

ProxyError — Повідомляє про помилку, що виникла під час роботи проксі.
RequestLogEntry — Зберігає запис про виконаний запит.
ProxyRuntime — Управляє активним проксі-процесом, дозволяючи його зупинити.
proxy_start — Ініціює роботу проксі-сервісу.
proxy_stop — Зупиняє активну роботу проксі-сервісу.
proxy_history — Повертає список попередніх запитів, оброблених проксі.
proxy_clear_history — Очищає збережений список попередніх запитів.

## Гарантії поведінки

- Перехоплює помилки і не пропускає винятків назовні (fail-safe).
- За певних помилок повертає порожнє значення (напр. `null`) замість винятку.

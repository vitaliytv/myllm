# proxy.rs

## Огляд

Модуль функціонує як зворотний проксі для трафіку `/v1/*` до omlx. Він слугує посередником для клієнтів (`mlmail`, `myshare`, `mcp-omlx.mjs`), які звертаються на локальний порт проксі замість прямого доступу до `:8000`. Проксі пересилає запити на omlx один в один, паралельно стрімячи копію в лог. Це дозволяє фіксувати повну історію взаємодії, оскільки Admin API (`admin.rs`) надає лише поточний стан черги. Модуль керує життєвим циклом проксі-сервера (`proxy_start`, `proxy_stop`) та надає механізми для доступу до збереженої історії (`proxy_history`, `proxy_clear_history`). При перехопленні мережевих помилок проксі працює в режимі fail-safe, не кидаючи винятків назовні, а повертаючи порожнє значення замість винятку за певних умов.

## Поведінка

ProxyError описує можливі помилки, що виникають під час роботи проксі.
RequestLogEntry описує структуру даних, що зберігає повну історію запитів та відповідей.
ProxyRuntime зберігає хендл живого проксі-таска для управління його життєвим циклом.
proxy_start запускає проксі-сервер на вказаному порту, використовуючи базовий URL для відправки запитів.
proxy_stop припиняє роботу запущеного проксі-сервера.
proxy_history зчитує та повертає останні записи з логу історії запитів.
proxy_clear_history видаляє весь вміст файлу логу історії запитів.

## Публічний API

ProxyError — інформує про помилку, що виникла під час роботи проксі.
RequestLogEntry — фіксує окремий запит, що пройшов через проксі.
ProxyRuntime — керує активним процесом проксі-таски, дозволяючи його зупинити.
proxy_start — ініціює роботу проксі-сервісу.
proxy_stop — припиняє роботу активного проксі-сервісу.
proxy_history — надає список усіх попередніх запитів, що пройшли через проксі.
proxy_clear_history — видаляє всі збережені записи про минулі запити.

## Гарантії поведінки

- Перехоплює помилки і не пропускає винятків назовні (fail-safe).
- За певних помилок повертає порожнє значення (напр. `null`) замість винятку.

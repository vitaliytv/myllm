# proxy.rs

## Огляд

Модуль реалізує зворотний проксі для трафіку `/v1/*` до omlx. Він виступає посередником, приймаючи звернення від клієнтів (`mlmail`, `myshare`, `mcp-omlx.mjs`) на локальний порт замість прямого звернення до `:8000`. Проксі пересилає запит на справжній omlx один в один і паралельно стрімить копію в лог. Це дозволяє збирати повну історію запитів та відповідей, оскільки Admin API omlx надає лише поточний стан. Завдяки цьому механізму стрімінг (SSE) не ламається для клієнта. Проксі перехоплює помилки (fail-safe) і не кидає винятків назовні, повертаючи порожнє значення замість винятку за певних умов.

## Поведінка

ProxyError описує можливі помилки, що виникають під час роботи проксі.
RequestLogEntry структурує дані одного запиту для збереження в лог.
ProxyRuntime керує життєвим циклом фонового процесу проксі.
proxy_start ініціалізує та запускає проксі-сервер на заданому порту, зберігаючи його хендл.
proxy_stop припиняє роботу запущеного проксі-сервера.
proxy_history зчитує та повертає останні записи з логу запитів.
proxy_clear_history видаляє весь вміст файлу логу запитів.

## Публічний API

ProxyError — Повідомляє про помилку, що виникла під час роботи проксі.
RequestLogEntry — Зберігає запис про виконаний запит.
ProxyRuntime — Управляє активним проксі-процесом, дозволяючи його зупинити.
proxy_start — Ініціює роботу проксі-сервісу.
proxy_stop — Примусово зупиняє роботу проксі-сервісу.
proxy_history — Повертає список попередніх запитів, оброблених проксі.
proxy_clear_history — Очищає збережений список попередніх запитів.

## Гарантії поведінки

- Перехоплює помилки і не пропускає винятків назовні (fail-safe).
- За певних помилок повертає порожнє значення (напр. `null`) замість винятку.

# chains.rs

## Огляд

Файл забезпечує кореляцію запитів проксі з ланцюжками `@nitra/llm-lib` шляхом читання глобального trace-файлу (`~/.n-cursor/llm-trace.jsonl`), де клієнт фіксує події ланцюжків, надсилаючи заголовки `x-chain-id`/`x-chain-step`/`x-chain-kind`/ `x-chain-cwd` з кожного локального виклику. Код спирається на конфігурацію, визначену в `garbage.json`. Обчислюється 16-символьний хеш (`prompt_hash`) останнього повідомлення з `role=="user"` з оригінального тіла запиту, що є дзеркалом контракту `llm-lib/lib/chain.mjs::promptHash`. Функціонал дозволяє переглядати список завершених ланцюжків та детальні кроки для кожного ланцюжка, а також зберігати та аналізувати ці ланцюжки. Усі операції обробляються з механізмом fail-safe, який запобігає викиданню винятків.

## Поведінка

ChainCorrelation зберігає кореляційні поля запиту, витягнуті із заголовків, та хеш промпту.
prompt_hash обчислює 16-символьний хеш останнього повідомлення користувача з тіла запиту відповідно до спільного контракту.
extract_correlation витягує кореляційні поля із заголовків запиту та обчислює хеш промпту з тіла запиту.
chains_list читає хвіст глобального trace-файлу та повертає список фінальних записів ланцюжків.
chain_steps читає хвіст глобального trace-файлу та повертає всі записи кроків для заданого ідентифікатора ланцюжка.
read_body_capture зчитує повні тіла кроків ланцюжка з body-capture стору за заданим ідентифікатором ланцюжка.
save_chain_analysis зберігає markdown-результат аналізу ланцюжка у файлі `.md` у каталозі insights та додає запис в індекс `chain-analyses.jsonl`.
list_chain_analyses зчитує індекс збережених аналізів з app-data та повертає список цих аналізів.

## Публічний API

ChainCorrelation — Збирає кореляційні дані з заголовків запиту та хеш промпту як запасний варіант.
prompt_hash — Генерує унікальний ідентифікатор для промпту на основі спільного контракту.
extract_correlation — Витягує кореляційні дані з заголовків запиту та обчислює хеш промпту з тіла.
chains_list — Подає список останніх завершених ланцюжків, розташовуючи новіші в кінці.
chain_steps — Перераховує послідовність кроків, що входять до одного ланцюжка, у порядку їх появи у файлі.
read_body_capture — Завантажує повні дані (запит та відповідь) для кожного кроку ланцюжка з відповідного сховища, якщо функція захоплення тіла активована.
save_chain_analysis — Зберігає детальний аналіз ланцюжка у форматі Markdown та оновлює індекс аналізів, повертаючи шлях до файлу.
list_chain_analyses — Повертає список усіх збережених аналізів для відображення в інтерфейсі.

## Гарантії поведінки

- Перехоплює помилки і не пропускає винятків назовні (fail-safe).
- За певних помилок повертає порожнє значення (напр. `null`) замість винятку.

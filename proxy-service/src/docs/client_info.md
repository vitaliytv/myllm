# client_info.rs

## Огляд

Модуль резолвить інформацію про процес, який ініціював HTTP-запит через проксі. Оскільки проксі слухає лише `127.0.0.1`, відомий локальний порт клієнта використовується для пошуку PID процесу-власника у системних TCP-сокетах. Далі, за PID, через `libproc` зчитується назва, шлях до бінарника та поточна робоча директорія. Резолв виконується на старті з'єднання, поки воно відкрите. Функціональність працює лише на macOS; на інших платформах резолв повертає `None`. Це дозволяє збагачувати історію проксі ідентифікацією процесу-клієнта.

## Поведінка

ClientInfo — Структура, що містить ідентифікаційні дані процесу-клієнта, який ініціював запит через проксі.
resolve — На macOS знаходить PID процесу, що тримає клієнтський бік TCP-з'єднання, і збирає повну інформацію про нього. На інших платформах повертає `None`.

## Публічний API

ClientInfo — зберігає інформацію про процес, що ініціював запит через проксі.
resolve — визначає процес, який використовує клієнтський порт для з'єднання з проксі, і збирає його дані.
resolve — знаходить процес, що володіє клієнтською частиною TCP-з'єднання, і збирає його дані.

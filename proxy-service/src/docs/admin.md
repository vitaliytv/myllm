# admin.rs

## Огляд

Реалізує прямий клієнтський доступ до адміністративних ендпоінтів реального omlx-сервера. Здійснює пряму комунікацію з адмін-ендпоінтами upstream-сервера, незалежно від порту локального реверс-проксі. Для доступу до `/admin/api/stats` та `/admin/api/global-settings` встановлює та підтримує сесію: сесія отримується через `/admin/api/login` за API-ключем, а потім використовується для подальших запитів. Код спирається на конфіги, зокрема `resp.json`. При виникненні помилок реалізує механізм fail-safe, перехоплюючи їх та повертаючи порожні значення замість винятків.

## Поведінка

AdminError описує можливі помилки, що виникають під час взаємодії з admin API.
Session містить клієнт для мережевих запитів та базовий URL для підтримуваної admin сесії.
AdminState зберігає поточну admin сесію у захищеному механізмі.
connect встановлює admin сесію, відправляючи запит на `/admin/api/login` з API-ключем та повертає об'єкт сесії.
current_session отримує поточну активну admin сесію з `AdminState`, якщо вона існує.
stats отримує статистичні дані з admin API, використовуючи активну сесію.
global_settings отримує глобальні налаштування з admin API, використовуючи активну сесію.

## Публічний API

AdminError — інформує про помилки, пов'язані з адміністративними операціями.
Session — керує активною сесією користувача.
AdminState — зберігає стан адміністратора у спільному об'єкті стану.
connect — встановлює з'єднання.
current_session — надає копію поточної сесії, звільняючи блокування.
stats — збирає статистичні дані.
global_settings — зберігає загальні налаштування системи.

## Гарантії поведінки

- Read-only: не виконує операцій запису (ФС/БД).
- Перехоплює помилки і не пропускає винятків назовні (fail-safe).
- За певних помилок повертає порожнє значення (напр. `null`) замість винятку.

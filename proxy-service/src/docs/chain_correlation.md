# chain_correlation.rs

## Огляд

Збирає кореляційні дані проксі-запитів, використовуючи заголовки `x-chain-*` та хеш останнього повідомлення користувача. Хеш (`prompt_hash`) генерується як sha256 перші 16 hex lowercase, де text — контент останнього повідомлення з role=="user" з оригінального тіла запиту. Ці дані записуються в `RequestLogEntry` (`proxy.rs`) для подальшого джойну з глобальним trace-файлом `~/.n-cursor/llm-trace.jsonl`, який читає `myllm` (вкладка «Ланцюжки»), забезпечуючи можливість відстежувати проксі-запити у контексті ланцюжків `@7n/llm-lib`.

## Поведінка

ChainCorrelation — структура для зберігання кореляційних даних проксі-запиту, включаючи ID ланцюжка, номер кроку, тип задачі, директорію виклику та хеш промпту.
prompt_hash — обчислює 16-символьний хеш (sha256) останнього повідомлення з роллю "user" у тілі запиту, використовуючи контент повідомлення.
extract_correlation — витягує кореляційні дані з заголовків запиту та обчислює хеш промпту з тіла запиту, повертаючи структуру ChainCorrelation.

## Публічний API

ChainCorrelation — Збирає кореляційні дані з заголовків запиту та використовує хеш промпту як резерв.
prompt_hash — Генерує унікальний ідентифікатор для промпту відповідно до встановленого стандарту.
extract_correlation — Видобуває кореляційні дані з заголовків запиту та обчислює хеш промпту з його вмісту.

## Гарантії поведінки

- Read-only: не виконує операцій запису (ФС/БД).
- Перехоплює помилки і не пропускає винятків назовні (fail-safe).
- За певних помилок повертає порожнє значення (напр. `null`) замість винятку.

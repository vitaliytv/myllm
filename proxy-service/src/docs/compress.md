# compress.rs

## Огляд

Модуль стискає тіло запиту `chat-completions` перед форвардом через `proxy_handler` (`proxy.rs`). Він мініфікує вбудований pretty-printed JSON у текстовому `content` та обрізає старі великі блоки повідомлень. Запит зі структурованим `response_format` пропускається цілком незмінним. Повідомлення, що містять `tool_calls`, `function_call` або `role: tool`, залишаються byte-exact по-повідомленнєвому. Для запитів, що перевищують `SYSTEM_TRUNCATION_SIZE_THRESHOLD`, захист `system`-повідомлення знімається. Канонічна логіка стиснення, визначена в `spec 2026-07-06-proxy-retirement`, реалізована в Rust-копії для проксі-шляху, але не є єдиним джерелом правди.

## Поведінка

1. Викликається функція compress_request_body для обробки тіла запиту.
2. Функція перевіряє, чи містить тіло запиту масив повідомлень. Якщо ні, повертається `None`.
3. Функція перевіряє, чи містить тіло запиту поле structured response_format. Якщо так, повертається `None`, і запит не змінюється.
4. Визначається, чи є повідомлення системним, і чи перевищує сумарний розмір сирого тіла запиту поріг SYSTEM_TRUNCATION_SIZE_THRESHOLD.
5. Визначається індекс останнього повідомлення, яке не підлягає захисту від обрізання (PROTECTED_TAIL_MESSAGES).
6. Ітерується по кожному повідомленню в масиві.
7. Якщо повідомлення містить tool_calls, function_call або має роль "tool", воно копіюється без змін.
8. Для інших повідомлень визначається, чи є воно системним, і чи знаходиться воно в захищеному хвості.
9. Для кожного повідомлення викликається compress_message.
10. Якщо повідомлення містить контент типу String, викликається compress_text.
11. У compress_text спочатку виконується minify_embedded_json для стиснення вбудованого JSON.
12. Якщо повідомлення захищене або після мінізації його розмір не перевищує TRUNCATE_THRESHOLD, воно приймається як є.
13. Якщо повідомлення не захищене і перевищує TRUNCATE_THRESHOLD, виконується обрізання тексту за допомогою truncate_middle.
14. Якщо повідомлення містить контент типу Array (мультимодальний), викликається compress_parts.
15. У compress_parts ітерується по частинах, і для текстових частин викликається compress_text.
16. Якщо будь-яке повідомлення було змінено, створюється новий об'єкт тіла запиту з оновленим масивом повідомлень.
17. Якщо жодне повідомлення не було змінено, повертається `None`.
18. Інакше, повертається новий об'єкт тіла запиту.

## Публічний API

compress_request_body — стискає тіло запиту на чат-відповіді, якщо це можливо.
